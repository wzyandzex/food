# 开饭 KaiFan 管理端信息架构与设计规范 (Admin IA & UI)

本文档定义管理运营工作台的全新信息架构（IA）、路由分发体系、布局组件设计与设计系统规范。

---

## 1. 原有问题与重构动因

- **原版核心缺陷**：将 JSON、Excel、LLM、URL、OCR、AI 配置等大量功能入口制作成大卡片纵向堆叠在首页，造成管理后台像“静态功能展示大厅”，缺乏高信息密度的运营管理流转体系。
- **重构原则**：
  - **工作流中心**：以“监控看板 -> 导入任务排队 -> 待审工单处理 -> 资产维护”为闭环。
  - **缩短操作路径**：统一侧边栏导航，直达各功能模块。
  - **视觉语义一致**：统一采用 `lucide-react` 矢量图标系统，剔除杂乱 Emoji，建立标准配色与表格规范。

---

## 2. 七大核心一级模块体系

```text
[开饭运营工作台]
  ├── 1. 总览看板 (/)
  │      ├── 运营指标卡片 (已上架菜谱、待审工单数、运行中任务、异常失败数)
  │      ├── 运营待办预警 (待审提醒、失败排查直达)
  │      ├── 最近任务流水
  │      └── 系统健康度与最近审计动态
  │
  ├── 2. 菜谱资产库 (/recipes)
  │      ├── 菜谱全量检索与筛选
  │      ├── 标签、耗时、份量、状态与来源管理
  │      └── 上架、下架、归档控制
  │
  ├── 3. 导入任务中心 (/jobs)
  │      ├── 选项卡工作区 (AI 批量生成 / URL 抓取解析 / JSON 批量导入)
  │      ├── 异步任务排队流水与实时进度条
  │      └── 任务明细抽屉与「仅重试失败项」
  │
  ├── 4. 审核中心 (/review)
  │      ├── 待审菜谱工单列表
  │      ├── 来源标记、难度与耗时展示
  │      └── 一键「通过并发布」与「驳回废弃」
  │
  ├── 5. 用户与准入 (/users)
  │      ├── 注册用户档案列表
  │      ├── 角色权限分配 (User / Admin)
  │      └── 邀请码追踪
  │
  ├── 6. 数据与监控 (/analytics)
  │      ├── 核心业务资产统计 (菜谱、食材、做饭、点单)
  │      └── 零成本免费配额预警评估 (Postgres 容量、Storage 容量)
  │
  └── 7. 系统设置 (/settings)
         ├── 动态 LLM API Key / 端点热插拔 (无需重启应用)
         ├── 敏感密钥自动掩码
         └── 在线连通性检测
```

## 3. 设计规范 (UI & Design System)

1. **色彩系统**：
   - **主品牌色 (Primary)**：暖色琥珀金（Amber-600 `#d97706`），代表做饭温情与食欲。
   - **成功色 (Success)**：翡翠绿（Emerald-600 `#059669`），用于任务成功、通过发布、系统健康。
   - **警告色 (Warning)**：琥珀橙（Amber-500 `#f59e0b`），用于排队中、待人工审核工单。
   - **危险色 (Destructive)**：珊瑚红（Red-600 `#dc2626`），用于任务异常、驳回废弃、网络超时。
   - **中性色 (Neutral)**：高品质浅灰底面（`bg-neutral-50/60`）配合深碳灰文字（`text-neutral-900`），保证高对比度与易读性。
2. **排版与密度**：
   - 数据展示优先采用带斑马纹/Hover 动效的精简紧凑表格（Padding 12px~14px）。
   - 状态展示采用药丸状 Badge，配合轻边框（`border`）增强视觉层级。
   - 避免单屏只显示 1~2 张巨大卡片，提升单屏数据吞吐量。
