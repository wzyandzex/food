# M2 独立购物清单模块（支持勾选已备齐）实现方案

## 1. 目标与范围
打造一个手机优先、交互流畅的独立「购物清单」模块（`/shopping-list`）：
- **查看与管理**：查看当前需要采购的食材清单，支持按「待备齐」与「已备齐」分类；
- **核心交互（勾选已备齐）**：买菜或在厨房准备时，点击条目即时切换 `checked` 状态（划线变灰），乐观更新 UI + 后端实时持久化；
- **多来源接入**：
  1. 从「点单汇总页」一键导入缺失食材（已有触发点，需完全联动）；
  2. 从「菜谱详情页」一键加入该菜谱食材；
  3. 支持在购物清单页面手动新增自定义食材/用品（如调料、保鲜袋等）；
- **清单管理**：支持修改数量/单位、删除单项、一键清除「已备齐」项、一键清空全部清单；
- **首页入口**：在主页增加「🛒 购物清单」卡片与未备齐项红点/数量角标。

---

## 2. 接口与数据流设计

### 2.1 后端 API 补全（`apps/web/src/app/api/shopping-lists/`）
- `GET /api/shopping-lists`
  - 获取当前登录用户的最新/活跃购物清单（若无则返回空列表或自动创建空白清单）；
- `POST /api/shopping-lists`
  - 追加或合并食材到当前清单（若已存在同名食材，智能合并数量）；
- `PATCH /api/shopping-lists/[id]`
  - 更新整单条目列表或单项状态（切换某项 `checked`，修改 `name`/`qty`/`unit`，过滤已备齐项）；
- `DELETE /api/shopping-lists/[id]`
  - 清空或删除该购物清单。

### 2.2 共享 Schema 与类型定义（`packages/shared`）
在 shared 包中补充购物清单条目与更新请求的 Zod Schema：
```ts
export interface ShoppingListItem {
  id: string // 前端唯一标识，便于列表渲染与局部更新
  name: string
  qty?: number | null
  unit?: string | null
  checked: boolean
  sourceRecipeTitle?: string // 来源菜谱名（可选）
}
```

## 3. 前端界面与交互设计

### 3.1 独立页面：`apps/web/src/app/shopping-list/page.tsx`
- **顶部统计**：显示「共 X 项，待采购 Y 项，已备齐 Z 项」以及完成进度条；
- **快速添加栏**：输入框支持快速录入（如 `牛肉 500g` 或 `生抽`），回车即加入清单；
- **待采购列表（Unchecked）**：
  - 醒目大复选框，易于单手点按；
  - 标注食材名称、数量、来源（如有）；
  - 点击左侧勾选框直接变为已备齐，触发轻触动效；
  - 支持右滑或编辑按钮调整数量；
- **已备齐列表（Checked，折叠/置底）**：
  - 勾选后的项沉底并带删除线，保留可反选恢复能力；
  - 底部操作栏提供「一键清理已备齐项」和「分享清单文本（复制到微信发给跑腿人）」。

### 3.2 多触点联动增强
- **主页 `apps/web/src/app/page.tsx`**：
  - 显式展示「🛒 购物清单」模块卡片，动态拉取待采购项数量；
- **菜谱详情页 `apps/web/src/app/recipes/[id]/page.tsx`**：
  - 食材栏新增「将未有食材加入购物清单」按钮；
- **点单汇总页 `apps/web/src/app/orders/[id]/page.tsx`**：
  - 完善「一键存为购物清单」操作，保存成功后直接提供跳转到购物清单按钮。
